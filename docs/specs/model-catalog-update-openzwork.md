# 一键更新模型资料（OZ-F015）

## 范围

在供应商设置的模型列表标题旁点击“更新模型”，按已添加模型的名称匹配 models.dev，将资料和推理档位写成原有模型编辑器使用的个人覆盖规则。内置继承和个人添加的模型均参与匹配，更新只写现有模型。

## 使用

弹窗显示按名称匹配的数量、已写入的模型和字段、推理档位变化、未匹配的模型，以及因目录分歧跳过的字段。零写入时显示“本次未更新模型资料”。目录变化时，只补全空缺或刷新本功能写过且用户没改过的字段。

## 所有者与顺序

- 所属 Environment 的 ProviderSettingsService 是更新入口；Renderer 不读写文件，也不接触目录网络请求。
- Node 目录 adapter 只 GET 固定的 `https://models.dev/api.json`，经 Host API 网络出口，沿用应用代理、No Proxy 和自定义 CA。不携带供应商凭据，禁止重定向，20 秒总超时，16 MiB 响应上限。错误码固定为 `catalog-timeout`、`catalog-request-failed`、`catalog-invalid-response`、`catalog-response-too-large`。
- 域模块取模型 ID 的最后一段，忽略大小写和首尾空白，将连续的空格、下划线和连字符统一。借鉴内置 `modelMatch` 的写法，按整个名称识别 DeepSeek V4.1 Flash、Claude Haiku 4.5、Opus 4.8、Fable 5.1 和 Mythos 5.1 的点号与连字符别名。日期和变体参与匹配，原始 ID 用于配置保存。
- 上下文、最大输出等资料在全目录同名条目中逐字段取过半值。每个目录供应商对同一字段最多一票，缺值或自身条目有分歧时弃权。存在目录值但没有过半值的字段列为跳过。
- Facade 在既有供应商操作队列中读取最新快照，计算补丁，再由 ConfigService 在一次 PersonalRepository 事务中写入。事务内重新检查成员、固定模式和已设置字段，任何校验失败都不留下半份更新。
- 内置继承与个人添加的模型都会更新。内置模型的更新写成 Personal 覆盖层里的精确 `provider-model` 规则（推荐模式部分覆盖），内置配置文件和内置模型列表从不修改。固定（手动）配置模式的模型整条保留。
- 字段归属：个人配置文件 `config.catalogManagedFields` 按供应商/模型记录本功能写过的字段及最后写入值，和个人规则在同一次 PersonalRepository 原子写里落盘，重启后仍有效。每次点击在事务内按下列规则判断：
  - 个人配置有值、记录里没有 → 用户设置，永不改。
  - 记录里有、且个人值仍等于记录值 → 目录管理：目录给出不同新值就刷新并更新记录；目录不再提供则保留。
  - 记录里有、但个人值已被用户改过 → 归用户：不改，并从记录删除（之后一直按用户设置对待）。
  - 个人配置没有值 → 目录值与当前生效值不同时写入并记录。
  - 模型删除/改名或改为固定模式时，相应记录一并清除。整份导入/替换个人配置可能不带记录，此时相关字段退化为用户设置（只会少刷新，不会覆盖用户值）。
- 可写字段：上下文窗口、最大输出、工具调用、结构化输出、输入/输出模态、推理档位（`optionSpecs.reasoningLevel.values`）。enabled、模型顺序、默认选择、其他供应商都不变。
- 推理档位只取 models.dev 的 `reasoning_options`，不编造：
  - `effort.values` 原样作为档位；同时有 `toggle` 且档位里没有 none/disabled 时，在最前面补仓库既有的关闭档 `disabled`。
  - 只有 `toggle`：与默认“关闭/开启”一致，不改也不报（不会把已有多档降级）。
  - `reasoning=true` 但没有任何选项时报告目录缺少档位信息；只有 `budget_tokens` 时报告目录仅提供思考预算范围。
  - 按目录顺序取首个明确列出至少两种推理强度的列表，开关标签不算强度。只有单档列表时采用首个明确列表。按内置规则使用的 `optionSpecs.reasoningLevel.values` 写入当前环境的 `provider_config.json`，保留目录列表的顺序和拼写。
- 上游内置目录文件不变。所有写入进入 Personal 覆盖层，后续上游合并不会重写此层。
